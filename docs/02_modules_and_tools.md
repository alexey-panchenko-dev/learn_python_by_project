# Модули, окружение и зависимости

## Виртуальное окружение

`.venv` изолирует библиотеки проекта от системного Python. Активация меняет путь,
по которому shell ищет `python` и `pip`; она не «включает Python».

Для прохождения курса на Windows рекомендуется **Python 3.13**: это зрелая ветка,
для которой у учебного стека меньше сюрпризов. Код совместим с установленным у
тебя Python 3.14.2, но в проверенном окружении связка pytest с некоторыми
нативными библиотеками зависала уже после отметки `100%`. Сам API при этом
запускается нормально. Установленные версии можно выбирать командами `py -0p`
и `py -3.13 -m venv .venv`.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e . --group dev
```

`python -m pip` гарантирует, что pip относится к выбранному интерпретатору.
`-e .` ставит текущий проект в editable-режиме. Группа `dev` содержит инструменты,
которые не нужны запущенному production API.

## pyproject.toml

Это центральный конфигурационный файл современного Python-проекта: metadata,
зависимости и настройки pytest/ruff. Ограничение `>=x,<y` разрешает совместимые
обновления, но не внезапный следующий major.

## Команды

- `fastapi dev app/main.py` — development server с autoreload;
- `uvicorn app.main:app` — импортирует объект `app` из модуля `app.main`;
- `pytest` — находит `test_*.py` и запускает тесты;
- `ruff check .` — статические ошибки и стиль;
- `ruff format .` — единообразное форматирование;
- `alembic upgrade head` — применяет все миграции.

## Как читать traceback

Начни с последней строки: тип и сообщение ошибки. Затем двигайся вверх до первого
кадра из своего проекта. Не исправляй первую увиденную строку наугад: сформулируй,
какое предположение программы оказалось ложным.

# Пароли, авторизация и JWT

Authentication отвечает «кто ты?», authorization — «что тебе разрешено?».

## Регистрация

Пароль проходит ограничения, затем Argon2 создаёт salted hash. В БД хранится
только digest. Хеш необратим: при входе библиотека проверяет кандидат, не
«расшифровывает» пароль.

## Вход и Bearer

После проверки сервер подписывает JWT секретом. Клиент отправляет:

```text
Authorization: Bearer eyJ...
```

JWT состоит из header, payload и signature. Payload кодирован, но не зашифрован:
туда нельзя класть пароль и другие секреты. Signature доказывает, что содержимое
не изменили. `exp` ограничивает срок, `sub` хранит id пользователя.

## Ограничения учебной реализации

Для production обычно нужны refresh tokens или повторный вход, отзыв сессий,
ротация секретов/ключей, rate limiting, аудит и HTTPS. Они не добавлены, чтобы не
прятать базовый поток. Секрет должен приходить из secret manager/окружения, а не
из Git.

401 применяется, когда токен отсутствует/невалиден. 403 — когда пользователь
распознан, но операция ему запрещена. Проект часть бизнес-конфликтов возвращает
как 409; в своём проекте документируй выбранную политику последовательно.

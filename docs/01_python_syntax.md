# Синтаксис Python, встречающийся в проекте

## Переменные и объекты

```python
status = "waiting"
moves = []
```

В Python переменная — имя, ссылающееся на объект. `status: str` — подсказка типа,
а не создание отдельного runtime-типа. Python остаётся динамическим, но редактор,
линтер и читатель получают контракт.

## Коллекции

- `list[str]` — упорядоченный изменяемый список;
- `tuple[int, int]` — упорядоченная, обычно неизменяемая группа;
- `dict[str, int]` — пары ключ/значение;
- `set[str]` — уникальные значения;
- `Thing | None` — либо объект, либо отсутствие значения.

Индексы начинаются с нуля. `board[1][2]` — третья клетка второй строки.

## Условия и циклы

```python
if cell:
    return "occupied"
elif row < 0:
    return "invalid"
else:
    return "free"

for move in moves:
    board[move.row][move.column] = move.symbol
```

Отступы образуют блоки. Пустая строка, `0`, `None` и пустая коллекция считаются
ложными. `==` сравнивает значения, `is None` проверяет именно объект `None`.

## Функции

```python
def calculate(a: int, b: int = 1) -> int:
    """Docstring объясняет контракт."""
    return a + b
```

`a` обязателен, у `b` есть значение по умолчанию, `-> int` описывает результат.
Не используй изменяемый объект вроде `[]` значением по умолчанию.

`*` в `def get(id, *, for_update=False)` делает последующие аргументы только
именованными: `get(id, for_update=True)` читается лучше.

## Классы и self

Класс описывает устройство объектов. `self` — конкретный экземпляр слева от
точки. Вызов `game.make_move(0, 1)` передаёт `game` как `self` автоматически.
`__init__` инициализирует новый экземпляр. Имена вида `__something__` —
специальные методы Python; не изобретай их произвольно.

## Dataclass и ORM-класс

`@dataclass` генерирует бытовые методы для класса данных. ORM-класс SQLAlchemy
выглядит похоже, но описывает ещё и SQL-таблицу. Это разные инструменты.

## Декораторы

```python
@router.get("/games")
def list_games(): ...
```

Декоратор получает функцию и регистрирует/оборачивает её. FastAPI сохраняет
функцию как обработчик GET-запроса. `@lru_cache` запоминает результат функции.

## Comprehension и generator expression

```python
ids = [game.id for game in games]
all_free = all(cell == "" for row in board for cell in row)
```

Первое сразу создаёт список. Второе лениво отдаёт значения функции `all`.
Сначала умей написать обычным циклом; затем сокращай, если чтение не ухудшается.

## Исключения

```python
try:
    game.make_move(row, column)
except GameError as error:
    raise HTTPException(409, detail=str(error)) from error
```

`raise` прерывает обычный поток. Лови конкретную ожидаемую ошибку, не голый
`except`. `from error` сохраняет причинную цепочку в traceback.

## Импорты, модули и пакеты

Каждый `.py` — module. Папка с `__init__.py` — package.
`from app.services.games import GameService` импортирует имя из модуля.
Импорт выполняет верхнеуровневый код один раз, поэтому избегай тяжёлой работы там.

## async, await, async with и yield

`async def` создаёт coroutine. `await` отдаёт управление event loop, пока ждёт
I/O. `async with` гарантирует асинхронное открытие/закрытие ресурса. Dependency с
`yield` выполняет код до `yield`, отдаёт ресурс route, затем выполняет cleanup.

CPU-вычисление от `async` быстрее не становится.

## assert

`assert condition` означает «в этой точке условие обязано быть истинным». Это не
валидация пользовательского ввода: assert можно отключить, а клиенту нужен
нормальный ответ. В проекте он фиксирует уже доказанный инвариант.

## Подчёркивания

`_games` — соглашение «внутренняя деталь». `_ = current_user` явно показывает,
что dependency нужна ради проверки, хотя значение дальше не используется.
Python не делает такое поле по-настоящему private.
